## Phase Hδ: PNG エクスポート（v1 必須）

> **位置づけ**: v1 出荷ラインの「PNG 書き出し → 共有シート」を満たすマイルストーン。保存（Hγ）は完了済み。下絵・編集クロムを含まない **完成物としての標準 PNG** を、端末ギャラリー保存および OS 共有シート経由で出力する。

### 要件（`plan_future_phases.md` から移行）

- **標準 PNG** をデバイスのギャラリーへ保存（`gal` 等）。
- **下絵なし出力で可**（編集中の underlay / 透過プレビュー／選択ハイライト／頂点ハンドルは含めない。確定ポリゴンの不透明塗り＋ストロークのみ）。
- **共有シート経由**の書き出し（`share_plus` 等）も提供する。
- 無料枠は標準 PNG。高解像度／透かし無し／SVG は v1.1 以降（エンタイトルメント継ぎ目は将来用）。
- UI 言語は v1.0 規約どおり **英語**（Tooltip / SnackBar 等）。

### 完了条件

- 空でない作品から PNG を生成し、ギャラリー保存と共有シートの両経路が動作する。
- 下絵・編集 UI クロムが PNG に混入しない。
- 権限拒否・失敗系でクラッシュしない（ユーザー向けメッセージを表示）。→ 技術的負債 #19、統合 smoke 項目 5〜6。
- `flutter analyze` / `flutter test` パス。実機でギャラリー保存・共有・権限拒否を確認。

### アーキテクチャ上の境界（実装時）

- サムネイル用 `RepaintBoundary` キャプチャ（Hγ）と **エクスポート用レンダラは分離**する（画面上の編集見た目をそのまま焼かない）。
- レンダラはマウント中ウィジェットに依存しないこと（将来のバックグラウンドキューにも耐える）。
- `ExportController` 等は失敗を swallow せず、呼び出し側が SnackBar 等で通知できる結果／メッセージを返す（#19）。

## リスクと対策（Hδ）

1. **OOM / メモリ圧迫**  
   - 高解像度キャンバスや大量ポリゴンをフル解像度で `toImage` すると端末メモリを圧迫しうる。  
   - 対策方針: 出力解像度の上限またはダウンサンプル方針をギャップ監査で確認し、必要なら上限を設ける。Hα の下絵 OOM 対策（#18）とは別経路だが、同種のリスクとして扱う。  
   - `Picture` / `Image` は必ず dispose する（既存レンダラの finally パターンを維持）。

2. **権限エラー・失敗系（#19）**  
   - ギャラリー権限拒否、ディスク満杯、共有シート失敗、レンダ null。  
   - 対策: 例外をアプリ全体に投げず、ユーザー向け英語メッセージを表示。テストで「hang / crash しない」を固定。

3. **編集見た目の混入**  
   - サムネ経路や `RepaintBoundary` を流用すると下絵・透過・選択枠が焼き付く。  
   - 対策: エクスポート専用レンダラのみを使う（要件どおり下絵なし）。
